# 项目边界与事实来源

## 适用范围

本规则适用于仓库内的代码、测试、文档和 `.claude` 配置维护。

## 事实来源

发生冲突时按以下优先级核实：

1. 当前源码与测试。
2. `pyproject.toml`。
3. `.pre-commit-config.yaml`。
4. 根目录 `CLAUDE.md`。
5. `.claude/skills/penshot/` 和 `docs/` 中的说明。
6. 历史报告、示例和生成性导览。

文档和回复必须区分：

- **已确认**：可由当前源码、配置或测试直接证明。
- **设计目标**：文档或计划中的目标，尚未证明已实现。
- **待验证**：需要运行测试、访问外部服务或进一步检查才能确认。

## 架构边界

- 接入层负责 SDK、REST、MCP 和 CLI 的协议适配。
- 任务层负责提交、排队、生命周期、仓储和工作流实例管理。
- 工作流层负责状态、节点、条件路由、检查点和输出。
- Agent 层负责领域处理，并遵循现有基类、rule/llm、factory 和 wrapper 结构。
- 知识与记忆层负责记忆、向量检索和模板知识。

新增功能应先定位现有扩展点，避免跨层直接访问内部实现或新增平行架构。

## 变更联动

- 新工作流阶段必须同步检查节点枚举、节点注册、边、决策函数、状态类型和测试。
- 任务状态变更必须检查生命周期服务、仓储、处理器、恢复逻辑和测试。
- 配置变更必须检查 YAML、环境变量映射、Pydantic Settings 和运行时配置。
- 对外接口变更必须检查 SDK、REST、MCP、CLI 和序列化模型。

不要把历史版本、完成度报告、部署方案或性能指标直接写成当前能力。
