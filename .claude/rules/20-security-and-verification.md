# 安全与验证规则

## 凭据与敏感数据

- 共享 settings、skill、rule、文档、日志和测试输出不得包含真实 API key、token、Authorization header、私有凭据或 `.env` 内容。
- 凭据只能通过本地环境变量或受保护的密钥管理方式注入。
- 日志、异常和调试输出必须脱敏；不得为了排查问题打印完整请求头、完整 prompt 或外部响应中的凭据。
- 修改或审查本地敏感配置时，不要将其内容复制到版本库文件。

## 外部副作用

- 默认不执行部署、发布、数据删除、缓存清理、数据库迁移、远程写操作或真实 LLM 请求。
- 需要外部服务时，先核实环境、目标和操作范围；优先使用现有测试替身和本地测试。
- 不通过隐式 shell 调用绕过项目边界或权限控制。

## 验证证据

- 结论必须说明依据：源码、配置、测试结果或外部依赖状态。
- “已通过”只用于本次实际执行并成功的检查。
- 对未运行、失败或因环境缺失无法运行的检查，明确记录状态和原因。
- 不把设计目标、历史报告、示例输出或静态文档当作运行证据。

## 安全变更

发现疑似泄露的凭据时：

1. 不在回复、日志或新文件中重复其内容。
2. 建议维护者撤销并轮换凭据。
3. 检查忽略规则和 Git 状态，避免再次纳入共享文件。
4. 只在用户明确要求且确认范围后处理删除、提交或远程操作。
